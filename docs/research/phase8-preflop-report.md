# Phase 8：翻前范围推断闭环（F5 真闭环）配对验收报告

日期：2026-09-26。机制：`preflopRangeModeEnabled`（brain.ts）+ `preflopRaiserRangePct`
与 `PREFLOP_VS_RANGE_EQUITY` 静态表（range.ts）。

## 机制与口径

审计遗留 F5：翻前面对加注时 brain 用静态百分位表（169 型 hot-and-cold，对随机
胜率口径），不按加注者范围算真实胜率。本相位补齐闭环：

- 加注者范围宽度按「身后人数」分档（`preflopRaiserRangePct`，近似值）：
  身后 ≥6 → 顶部 15%；4-5 → 20%；2-3 → 28%；1 → 40%；0/单挑按钮 → 55%。
- 手牌对该范围的真实胜率来自离线静态表 `PREFLOP_VS_RANGE_EQUITY`
  （169 牌型 × 5 档范围宽度；`scripts/selfplay/gen-preflop-range-table.ts`
  蒙特卡洛每格 4000 次迭代、固定种子可复现、逐行「范围越宽胜率不减」单调修整，
  修正格 69/845，修正量 << 1 个标准误）。范围 = PREFLOP_ORDER 前 ceil(169×X)
  牌型的全部组合（对子 6 / 同花 4 / 非同花 12 天然加权）。
- 决策判定改为绝对胜率口径：对范围胜率 ≥ 风格价值 3bet 门槛（0.58-0.67）→
  3bet（IP 3x / OOP 4x）；≥ 跟注门槛（0.42-0.48）→ 跟注；边缘可玩牌诈唬
  3bet（带宽旋钮复用）；其余弃牌。风格增量、剥削（facingRaiseDelta）、ICM
  收紧、大盲关门折扣（-0.06）、便宜跟注折扣（-0.04）同量叠加到胜率门槛。
- 与 `preflopPosAdjustEnabled` 的关系：范围口径开启时旧旋钮失效（加注者位置
  信息已被范围宽度直接吸收），二者不叠加。
- 合成快照/行动序列缺失找不到加注者时按中位档 behind=3（≈28%）近似。
- 短筹码 push/fold（<15bb 顶端范围直接 all-in）沿用对随机百分位口径，不在
  本闭环范围；单挑大盲恒走 bb_defend 表分支，不受影响。

核心口径差异（静态百分位表无法表达、本闭环要捕捉的效应）：
- 中对子对紧范围显著缩水：77 对随机百分位 0.946（近似前 5%），但对 15%
  紧范围真实胜率仅 0.474，低于 AKs（0.606）——旧口径下 77 面对 UTG 加注
  被当作准 premium，新口径下回归「跟注/弃牌边缘」的真实定位。
- 被统治 Ax 缩水：A3o 百分位 0.679 但对 15% 范围仅 0.319 → 弃牌。
- 边界正确性：AA 对任何范围 ≥ 0.77（实测 0.843-0.868）；72o 对 15% 范围
  0.253 ≤ 0.35；同牌型随范围变宽胜率单调不减（生成时强制修整）。

## 判定

合并 CI 跨零（[-6.2, +16.9]）且中值 +5.3 < +15 采纳线 → **不采纳为新默认**，
`preflopRangeModeEnabled` 默认 **false**，机制保留供更大样本 A/B。
方向性备注：三种子全正（+3.3/+2.3/+10.4），合并中值为正但统计上不显著；
与 Phase 5 posadj（+4.8 [-2.2,+11.8]）同一量级——翻前防守口径修正在 100bb
固定深度下的净效应持续偏小，估计主战场在深筹/结转场景（护栏同逻辑）。
后续方向：200bb 深筹配对、或混合风格桌（Phase 6 协议）下复测。

## LLM 大底池 self-consistency 投票（同相位顺带交付，不做大样本）

- opponent.ts：LLM 模式下底池 ≥ 25bb（VOTE_POT_BB）或河牌街时并行采样 3 次
  （Promise.all，各自 8/15/25s 超时窗口），action.type 多数投票，平票按
  fold<check<call<bet<raise<allin 保守序取更保守者；bet/raise 金额取中位数
  （偶数票取下中位，保守）；3 次全失败才回退启发式；reasoning 合并三段
  （含归票统计）。旋钮 `LLMConfig.selfVote`（默认 undefined = 开）。
  生产透传待接线：readLLMConfig 在 gameStore（另一 agent 范围），本次只改
  opponent.ts 读 config.selfVote。
- 单测 `src/lib/ai/__tests__/opponentVote.test.ts`（14 例，vi.mock
  chatCompletion 控制三次返回）：触发条件（大底池/河牌/小底池不触发/
  selfVote:false）、多数投票、三方平票取 fold、两票平票取保守、金额中位数
  （含钳制后中位、偶数票下中位）、部分超时存活、全失败（抛错/垃圾文本/
  全挂起超时）回退、reasoning 三段合并。

## 遗留问题

1. `preflopRangeModeEnabled` 默认关闭待更大样本/深筹复测（方向为正）。
2. LLMConfig.selfVote 的生产透传（gameStore readLLMConfig）未接线——属另一
   agent 的文件边界；接线前生产行为 = 默认开启（undefined=开，符合规格）。
3. 静态表粒度 5 档，档间最近吸附有阶梯效应（如 0.24→0.20 档）；如需更细
   可重跑生成器加档。
4. 范围 = PREFLOP_ORDER 顶部 X% 的近似（真实开局范围含 65s 优先 K7o 之类的
   可玩性排序），注释已标明；升级方向是换成真实开局表（gto/ranges.ts 矩阵）。
