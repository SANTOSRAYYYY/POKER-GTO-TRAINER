## 逐变体解读

### v1：`valueRaiseFrac` 0.85 —— 旋钮在 gto 内战中是空操作

- 任务书给的旋钮名 `valueRaiseFracDefault` 在代码里**不存在**；`src/lib/ai/brain.ts:515` 的实际旋钮是 `valueRaiseFrac`（默认 0.7，与任务书描述一致），本实验已用正确拼写。
- 但 `brain.ts:883-885`：价值加注尺度按风格分支，`style === "gto"` 走 `valueRaiseFracGtoA(0.6)/GtoB(0.75)` 随机二选一，`valueRaiseFrac` **只在非 gto 风格分支被读取**。gto 内战里改它完全无效。
- 实测验证：8000 手配对，6 个座位 diff **全部精确为 +0.0**、CI [0,0] —— 两遍逐比特一致。这顺带是台架可复现性的完美 null control。
- 建议：若主办方想测「gto 价值加注更大尺度」，应实验 `valueRaiseFracGtoA/GtoB`（当前默认 0.6/0.75），本组未获授权改动这两个旋钮，未测。

### v2：`valueBetFracGtoA/GtoB` → (0.67, 0.85) —— 证据不足，点估计偏负

- gto 无人下注时的价值下注尺度（`brain.ts:913-914`），旋钮生效确认：座位 0 约 10% 的手（814/8000、738/8000）结果被改变。
- 两个种子点估计互相矛盾：seed42 −574.0（CI 宽 ±1210），seed43 +15.3（CI ±171）。合并 16000 配对手：−279.3 [−890.2, +331.5]，CI 跨 0。
- 方向解读：点估计偏负，符合扑克直觉 —— 对 gto 对手加大价值下注，对手按赔率正确弃掉更多差牌（多赢不了多少）、只用更强牌继续（输得更多），薄价值下注变大后 EV 反而变薄。但统计上远未显著，**按规则保持默认**。
- 若后续要定论此旋钮，需显著更多手数或降低 carry-over 深度（见「台架观察」）。

### v3：`bluffRaiseFrac` 0.75 —— 证据不足，轻微偏负

- 诈唬加注尺度（`brain.ts:900`，全风格生效），但触发条件苛刻（对手 ≤2、betFrac ≤1.2、eq ≥0.10、概率掷签）：8000 手中座位 0 仅 **49 手**结果不同（0.6%）。200 手 smoke 时 diff 精确为 0 即因零触发，非旋钮失效。
- diff −19.0 [−177.1, +139.0]：CI 跨 0 且中值小、方向偏负。低触发频率决定了该旋钮在 gto 内战里效应上限本就很小。**保持默认。**

## 台架观察（供主办方参考）

1. **配对差值方差被筹码结转放大。** stacks 跨手结转、破产才重置，深筹码后期会出现巨型底池：v2 差值单手 sd ≈ 394 bb，最大的单手 |diff| 达 27533 bb（27.5 万筹码，深筹码全下池）；top-10 大手贡献 40.3% 的总 |diff|。尺度类旋钮直接放大底池，受此影响最严重 —— seed42 的 −574 与 seed43 的 +15 的巨大反差即源于此。8000 手配对对尺度旋钮的统计功效有限。
2. **配对设计本身工作正常**：三场变体的 run A（基准）逐手一致（座位 0 bb/100 均为 +426.9）；v1 空操作变体 6 座位 diff 全为精确 0.0，证明发牌与决策流逐比特可复现。
3. v2 中座位 1（座位 0 下家）diff +509.3：座位 0 的亏损不对称地流向其下家，属正常位置效应。
4. 吞吐：并行高峰 ~4.5 hands/s，尾段 ~8.3 hands/s；单场 8000×2 手约 33–49 分钟。
